| :--- | :--- |
| **Status** | Active |
| **Owner** | maintainer |

This guide covers directory contents, backup strategies, safe cleanup practices, and procedures for migrating
data from previous layouts to the native runtime data root.

## Runtime directory structure

The runtime data root is organized into five main directories:

```
<data_root>/
├── models/       # Neural network weights (~15-20 GB)
│   ├── flux2/    # FLUX.2 shared components (Qwen3 text encoder, VAE)
│   ├── trellis2/ # TRELLIS.2 shared components (DINOv3 encoder, decoders)
│   ├── rembg/    # Background removal weights (isnet-general-use)
│   └── user/     # User-installed diffusion and flow weights
├── engines/      # Platform-specific engine runners and shared libraries (~1-5 GB)
├── library/      # Finished outputs and input uploads
│   ├── jobs/     # Job metadata, generated images, and exported 3D GLB meshes
│   └── uploads/  # Uploaded reference images
├── server/       # Configuration and logs (mode 0700)
│   ├── config.json   # Runtime user settings
│   ├── runtime.log   # Supervisor log output
│   └── server.log    # GPU job traces and memory metrics
└── venv/         # Runtime Python 3.12 virtual environment (~500 MB)
```

## Backup recommendations

To back up your configuration and creative assets without copying regenerable weights:

- **Essential to back up:**
  - `<data_root>/library/`: Contains your generated assets, input images, and job history.
  - `<data_root>/server/config.json`: Contains your custom step settings and timeouts.
- **Optional to back up:**
  - `<data_root>/models/`: Large downloads. Back up if internet bandwidth is constrained.
- **Do not back up:**
  - `<data_root>/server/runtime.json`: Ephemeral process state deleted on shutdown.
  - `<data_root>/server/*.log`: Ephemeral log files.
  - `<data_root>/venv/`: Automatically regenerated by `scripts/lp setup`.
  - `<data_root>/models/.cache/`: Temporary download staging files.

## What is safe to delete

When reclaiming disk space:

| Path | Safe to delete? | Consequence |
| :--- | :--- | :--- |
| `<data_root>/venv/` | Yes | Regenerated cleanly on the next `scripts/lp setup`. |
| `<data_root>/models/.cache/` | Yes | Temporary artifacts from downloads; safe to remove at any time. |
| `<data_root>/server/runtime.log` | Yes | Recreated on the next service startup. |
| `<data_root>/server/server.log` | Yes | Recreated on the next service startup. |
| `<data_root>/library/uploads/` | Caution | Deletes source upload files referenced by past jobs. |
| `<data_root>/library/jobs/` | Caution | Deletes historical generation results and GLB files. |
| `<data_root>/models/` | No | Forces redownloading weights on next run. |

## Relocating storage with `LP_HOME`

To move the data root to another disk or mount point:

1. Stop running services:
   ```bash
   scripts/lp down
   ```
2. Move the directory:
   ```bash
   mv ~/Library/Application\ Support/local-producer /Volumes/FastStorage/local-producer
   ```
3. Set the environment variable in your shell profile:
   ```bash
   export LP_HOME="/Volumes/FastStorage/local-producer"
   ```
4. Verify resolution:
   ```bash
   scripts/lp root
   ```

## Migration from legacy `~/.local-producer`

Previous versions stored runtime assets under `~/.local-producer`.
To migrate this tree to the standard native data root:

```bash
scripts/lp setup --migrate
```

Requirements and behavior:
- The destination data root must not already exist (or must be empty). If destination files exist, `--migrate` refuses to run to prevent accidental overwrites.
- The command moves the existing `~/.local-producer` directory into the new platform location, preserving file ownership and permissions.
- The runtime virtual environment is automatically created or refreshed in the new destination.

## Migration from legacy container volumes on Linux

If upgrading from an earlier container-based installation on Linux, models and engine packages previously lived inside named storage volumes.
The underlying files are located on the host disk at:

```bash
~/.local/share/containers/storage/volumes/<volume_name>/_data
```

To migrate these weights into the native data root:

1. Locate the volume paths:
   ```bash
   MODELS_SRC="$HOME/.local/share/containers/storage/volumes/local-producer-models/_data"
   ENGINES_SRC="$HOME/.local/share/containers/storage/volumes/local-producer-engines/_data"
   ```
2. Initialize the native data root:
   ```bash
   scripts/lp setup
   ```
3. Copy the weights and packages into the native tree:
   ```bash
   DEST=$(scripts/lp root)
   cp -a "$MODELS_SRC"/* "$DEST/models/"
   cp -a "$ENGINES_SRC"/* "$DEST/engines/"
   ```
4. Verify disk sizes match:
   ```bash
   du -sh "$MODELS_SRC" "$DEST/models"
   ```
5. Run diagnostics:
   ```bash
   scripts/lp doctor
   ```
