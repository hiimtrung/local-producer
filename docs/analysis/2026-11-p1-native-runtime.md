## 2. Goal

After P1, the server starts the same way on macOS and Linux, from the repository and from a desktop shell later:

- one Python process tree, started by `server/app/supervisor.py`, no shell entrypoint and no container;
- one plain data directory, resolved by `data_root()`, no Podman volumes and no bind mounts;
- one command to run it, `scripts/lp up`, backed by one environment definition, `server/app/runtime_env.py`;
- one lock file per OS, regenerated by a script and checked in CI, never by hand;
- no container tooling anywhere in the product or the developer workflow, and CI that proves the runtime works on
  `ubuntu-24.04` and `macos-14`.

What P1 explicitly does **not** do: no desktop app, no engine artifact changes, no compatibility scan, no token
default, no GPU code changes, no UI redesign.

## 4. Ground rules

- **English only** in every file, including comments, log lines and commit messages (`AGENTS.md`).
- **Measure, do not estimate.** Every number goes into `CHANGELOG.md` with its method and sample size. If n is 3, say
  n = 3 and give the range; do not present a range as a mean.
- **Facts and hypotheses are separate.** "bwrap failed on this Ubuntu" is a fact; "AppArmor caused it" is a
  hypothesis unless proven by the AppArmor setting you read.
- **Do not weaken security.** `SECURITY.md` currently promises engine CLIs no network access. P1 keeps that promise:
  macOS via `sandbox-exec`, Linux via `bwrap`. If `bwrap` is unavailable, the engine is **blocked with a readable
  reason**; the degraded fallback is a P6 decision that needs written approval. Do not implement it now.
- **Do not delete user data.** `lp setup --migrate` may move `~/.local-producer` to the new root after checking that
  the destination does not exist; it never merges, never overwrites, and prints what it did. Without `--migrate`, it
  only prints the command.
- **Do not touch** `web/` behaviour, the API surface, `server/app/pipelines/`, `model_store.py`, `model_setup.py`
  behaviour, the job/Library format, or the add-on's request format. Only `web/src/lib/token.ts` and the add-on
  discovery are excluded from "do not touch" **if** you reach the P3/P4 items — and you are not doing those in P1.
- **No new runtime dependency** unless it is already in `server/requirements.in`. New dev-only tools need a sentence
  in the plan review, not a silent addition.
- **Root `.md` files** may be rewritten as described in §7.9. That is the explicit approval required by `AGENTS.md`;
  any other root-file rewrite needs a request.

## 6. Target contract

### 6.1 Data root and layout

`data_root()` returns, in this order:

1. `$LP_HOME` if set (expanded, absolute);
2. macOS: `~/Library/Application Support/local-producer`;
3. Linux/other: `${XDG_DATA_HOME:-~/.local/share}/local-producer`.

Inside it, on both platforms:

```
<root>/
├── models/     weights (shared components + user/<id>/ main models)
├── engines/    installed engine packages + active.json
├── library/    jobs/<id>/ and uploads/            (the Library page)
├── server/     config.json, server.log, runtime.log, runtime.json
└── venv/       the server's Python 3.12 environment
```

`<data>` below means `<root>/server`; `<library>` means `<root>/library`.

Migration: the old macOS layout is `~/.local-producer` with the same subdirectories, so `lp setup --migrate` is a
one-time `mv` when the new root does not exist. Linux container users have data in Podman volumes; the migration
command for that is documented in §7.9 (`operations/backup-and-migrate.md`) and is **manual** — do not automate it.

### 6.2 Environment contract

One function produces the child environment; nothing else sets these variables.

| Variable | Value | Notes |
| :--- | :--- | :--- |
| `MODELS_DIR` | `<root>/models` | still honoured by `settings.Paths` for tests |
| `ENGINES_DIR` | `<root>/engines` | |
| `LIBRARY_DIR` | `<root>/library` | |
| `DATA_DIR` | `<root>/server` | |
| `U2NET_HOME` | `<root>/models/rembg` | rembg weights |
| `PYTHONDONTWRITEBYTECODE` | `1` | no `__pycache__` in the install tree |
| `PYTHONUNBUFFERED` | `1` | log lines appear immediately |
| `OMP_NUM_THREADS` | derived | macOS `hw.perflevel0.physicalcpu`; Linux `min(8, len(sched_getaffinity()))`; fallback `os.cpu_count()`; the 8 carries the container's value, not a new claim |
| `HOST_MODELS`, `HOST_ENGINES`, `HOST_LIBRARY`, `HOST_DATA` | human strings | shown by the UI and `doctor` |
| `SERVER_TOKEN` | pass-through if set | unchanged in P1; the supervisor does not create one |

### 6.3 Ports, files, exit codes

| Thing | Value |
| :--- | :--- |
| API + web UI | `127.0.0.1:13305`; if taken, an ephemeral port; the chosen port goes into `runtime.json` |
| Matting | `127.0.0.1:8083`, fixed; if taken, startup fails with a message naming the port |
| `runtime.json` | `<data>/runtime.json`, mode `0600`, written atomically after both health checks pass |
| `runtime.json` fields | `url`, `port`, `pid`, `version`, `started`; `token` is **not** written in P1 (P3/P4 add it), readers must tolerate its absence |
| Supervisor log | `<data>/runtime.log` (startup, both children, supervisor events; `lp up` also appends the supervisor's own stderr here), appended, never truncated at start |
| Job log | `<data>/server.log` (unchanged; the UI's Log page and `tail(200)`) |
| Exit codes | `0` after SIGTERM/SIGINT; `1` startup failure or health timeout; otherwise the first child's exit code |

### 6.4 `scripts/lp` commands

| Command | Behaviour | Exit |
| :--- | :--- | :--- |
| `lp setup [--migrate]` | create the layout; venv from `server/requirements.<os>.txt` (stamped by lock hash); build `web/dist` if missing/stale | 0, `1` on failure |
| `lp up [--foreground] [--no-matte]` | setup if needed, start the supervisor (detached unless `--foreground`), wait for health up to 180 s, print URL and log path | 0 ready, `1` failed |
| `lp down` | SIGTERM the supervisor's process group, wait 10 s, SIGKILL, wait for the port to close; leave `runtime.json` only if it belongs to another pid | 0 stopped or not running |
| `lp status` | pid alive + `/health` reachable; print url, version, engine state | 0 healthy, `1` otherwise |
| `lp logs [--lines N] [-f] [--jobs]` | tail `runtime.log` (default) or `server.log` (`--jobs`) | 0 |
| `lp root` | print the resolved data root (`Layout.resolve().root`) | 0 |
| `lp exec ARGS...` | run the venv python with the server environment, cwd `server/` (used by `make`) | the command's code |
| `lp doctor` | layout, venv version and imports, `web/dist`, engine + preflight, models, disk, ports, sandbox verdict | 0 if the server can start, `1` otherwise; warnings do not fail |

All commands honour `LP_HOME`. `lp` must not reference a container tool anywhere.

### 7.3 `supervisor.py`

**Files:** new `server/app/supervisor.py`; edit `server/app/main.py` (default host `127.0.0.1`, log line);
new `tests/test_supervisor.py`.

**Build:**

- CLI: `python -m app.supervisor [--port 13305] [--no-matte]`. There is no foreground flag: the supervisor always
  writes everything to `runtime.log` **and** echoes its own `[supervisor]` lines to stderr, so a manual run in a
  terminal is readable as it starts while `lp` detaches it (`lp up --foreground` means "do not detach", not a
  supervisor option).
- Resolve the layout, `ensure()`, build the child environment with `runtime_env.child_env`.
- Pick the API port: try the requested one; on `OSError` bind port `0`, close, use that port. Document the
  close-then-bind race as accepted in v1.
- Start the matting server **first**: `[sys.executable, "-W", "ignore", "matte_server.py", "--host", "127.0.0.1",
  "--port", "8083"]`, cwd `server/`. Skip it with `--no-matte` (CI, tests).
- Start the API: `[sys.executable, "-m", "app.main", "--host", "127.0.0.1", "--port", str(port)]`.
- Each child in its own process group (`start_new_session=True`). A reader thread per child merges stdout+stderr into
  `runtime.log`, one line at a time, prefixed `[api]` / `[matte]` and an ISO-8601 UTC timestamp; the supervisor's own
  lines are prefixed `[supervisor]`. Never let a partial line split across two log entries.
- Poll `http://127.0.0.1:<port>/health` and `http://127.0.0.1:8083/health` (unless `--no-matte`) every 0.5 s, up to
  180 s. Timeout: kill both groups, log one line naming `runtime.log`, exit 1.
- After health: write `runtime.json` atomically (`tmp` + `os.replace`, chmod 0600) with §6.3 fields, then log
  `ready: http://127.0.0.1:<port> (pid <pid>)`.
- Signals: SIGTERM/SIGINT → SIGTERM both process groups, wait up to 10 s, SIGKILL what remains, remove
  `runtime.json` only if it still contains this supervisor's pid, exit 0.
- Child exit: kill the sibling's group, wait, remove `runtime.json` under the same condition, exit with that child's
  code. If the API exits before health, startup fails with code 1 and the child's last log lines are already in
  `runtime.log`.
- No restart logic, no tray, no token generation in P1.

**Tests** (POSIX only): `pick_port` falls back when the preferred port is held; `runtime.json` is written with mode
0600 and replaced atomically (`os.replace`); a child that spawns a grandchild is killed with the group (spawn
`sys.executable -c` that starts a sleeper, assert both pids gone after shutdown); SIGTERM exits 0 and removes
`runtime.json`. Do **not** spawn the real API in unit tests; the CI runtime job does the end-to-end start.

**Result:** `python -m app.supervisor --no-matte` serves `/health`; SIGTERM leaves no process behind; `runtime.log`
contains both a `[supervisor]` and an `[api]` line.

### 7.4 `sandbox.py`

**Files:** new `server/app/engines/sandbox.py`; edit `server/app/engines/registry.py` (drop `SANDBOX_EXEC`,
`SANDBOX_PROFILE`, `_prefix`; call the module); new `tests/test_sandbox.py`; edit `tests/conftest.py` (`fake_host`
must neutralize the probe) and `tests/test_engines.py` (the macOS prefix assertion at the end moves to
`test_sandbox.py`).

**Build:**

```python
def prefix(host: HostInfo) -> tuple[str, ...]: ...   # what every engine CLI is started under
def problem(host: HostInfo) -> str: ...             # "" when the CLIs may run; why not otherwise
```

- macOS (`host.os == "macos"`): unchanged — `/usr/bin/sandbox-exec -p "(version 1)(allow default)(deny network*)"`
  when it is executable; otherwise `problem()` says so (do not silently run unsandboxed).
- Linux (`host.os == "linux"`): `bwrap` prefix
  `("bwrap", "--unshare-net", "--dev-bind", "/", "/", "--")`, after `problem()` has proven it works: `bwrap` is on
  `PATH` and `bwrap --unshare-net --dev-bind / / -- true` exits 0 within 5 s. If not: `problem()` returns one
  sentence naming what failed and the fix (`apt install bubblewrap`, and that the P6 fallback needs approval). Cache
  the probe per process; tests monkeypatch it.
- Any other OS: `problem()` says no sandbox is implemented for this platform, so engine CLIs are refused.
- Wire into `Engines.load()`: `problem = spec.platform.mismatch(...) or backends.preflight(...) or
  sandbox.problem(host) or self_test(...)`. `Runner.prefix` comes from `sandbox.prefix(host)`.

**Tests:** macOS prefix and missing `sandbox-exec`; Linux with/without `bwrap`; probe failure (non-zero, timeout);
blocked load message reaches `EngineStatus.problem`; `conftest.fake_host` patches `sandbox.problem` to `""` and
`prefix` to `()` so existing tests do not depend on the host.

**Result:** on the Mac, an engine load still uses `sandbox-exec`; on a Linux box without `bwrap`, the Engines page
shows one actionable sentence and no job starts; with `bwrap`, `make smoke` still passes on hardware (P2 verifies the
GPU path; P1 only verifies the CLI wrapper with the fake engine).

### 7.5 `scripts/lp`

**Files:** new `scripts/lp` (POSIX `sh`, ~30 lines: find an interpreter, `exec` the Python entry point), new
`scripts/lp.py` (Python 3.12, standard library only), new `tests/test_lp.py`; delete `scripts/lp-env.sh`,
`scripts/run-native.sh`, `scripts/run-server.sh`; edit `Makefile`; edit `pyproject.toml` (add `scripts/lp.py` to the
mypy `files` list and keep it under ruff); `server/app/main.py` only as in §7.3.

**Why two files.** The old scripts were bash and had to stay compatible with the bash 3.2 that macOS ships (no
associative arrays, no `mapfile`, no `${x,,}`), and none of that logic could be unit-tested. P1 moves every non-trivial
step to Python, where the runtime contract already lives, and keeps a small `sh` bootstrap so `scripts/lp` is still
one executable that works from any cwd and before any environment exists. `lp.py` imports `app.runtime_env`, so the
layout is defined once.

**Build `scripts/lp`** (`set -eu`, no bashisms):

1. `here="$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)"`.
2. Interpreter, first that works: `$LP_PYTHON`; `<root>/venv/bin/python` if executable; `python3` from `PATH`.
   `<root>` is computed with the four lines of §6.1 — this is the **only** duplicated fact in the whole change,
   because the bootstrap needs a Python before it can import anything. `lp root` and `tests/test_lp.py` prove the
   shell and `data_root()` agree.
3. Nothing usable: print one sentence (`lp needs Python 3.12; run 'uv python install 3.12' or set LP_PYTHON`) and
   exit 1.
4. `exec "$py" "$here/lp.py" "$@"`.

**Build `scripts/lp.py`** (one function per command, `main(argv)` returns an exit code):

- Refuse `sys.version_info < (3, 12)` with the sentence above, before importing anything else.
- `sys.path.insert(0, <repo>/server)`, then `from app.runtime_env import Layout, child_env`. `runtime_env` must stay
  standard-library-only, so this import works on a fresh checkout with no venv.
- Implement §6.4, including `lp root`. Subprocesses always get a list, never `shell=True`.
- `setup`: check `uv`; `uv venv --python 3.12 --allow-existing <venv>`; `uv pip sync --python <venv>/bin/python
  --require-hashes -r server/requirements.<os>.txt` (`linux` → `requirements.linux.txt`, `darwin` →
  `requirements.macos.txt`); write `<venv>/.lock.sha256` (SHA-256 of that lock file); rebuild the web UI when
  `web/dist/index.html` is missing or older than any file under `web/src`, `web/styles`, `web/vendor` (the
  `find -newer` test of the old script), with `npm ci --ignore-scripts` when `web/node_modules` is missing.
- `setup --migrate`: move `~/.local-producer` to the new root only when the old path exists and the new one does not;
  print the `mv` it runs; refuse anything else and say why (§4).
- `up`: read `runtime.json`; if its pid is alive and `/health` answers, print "already running" and exit 0. Run
  `setup` when the venv or `web/dist` is missing. Start `"<venv>/bin/python" -m app.supervisor --port 13305`
  (append `--no-matte`) with `cwd=<repo>/server`, `env=child_env(layout)`, `start_new_session=True`, stdin
  `/dev/null`, and stdout/stderr redirected in append mode to `<data>/runtime.log` (so a crash before the supervisor
  opens the log is still recorded there). With `--foreground`, do not detach: the supervisor inherits the terminal
  and `^C` reaches it. Then wait until `runtime.json` names a live pid **and** `/health` answers (0.5 s poll, 180 s
  limit, print the last lines of `runtime.log` on timeout and exit 1); print the URL, `runtime.log`, and the engine
  state from `/v1/system`; when the matting weights are still downloading, print a first-run note instead of failing.
- `down`: no `runtime.json` → "not running", 0. Stale pid → say so, remove the file, 0. Otherwise SIGTERM the
  supervisor (it stops its own children; it is in its own session, do not signal the group from outside), wait up to
  10 s, SIGKILL, then wait until `/health` stops answering; remove `runtime.json` only if it still names that pid.
- `status`: missing or stale → message and exit 1; else `GET /v1/system` with `urllib.request` (2 s timeout) and
  print url, version, engine id/version/`problem`, models ready; exit 1 when `/health` is not `ok`.
- `logs [--lines N] [-f] [--jobs]`: tail `runtime.log` (default) or `server.log`; `-f` polls every 0.2 s and stops on
  `KeyboardInterrupt`; a file shorter than N prints what it has.
- `exec ARGS...`: `os.chdir(<repo>/server)` then `os.execvpe(<venv>/bin/python, [python, *args], child_env(layout))`.
- `doctor`: the §6.4 checks, one `ok`/`warn`/`fail` line each, the fix printed under a `fail`; exit 1 only on `fail`.
- No container tool anywhere, and no token handling in P1.

**Tests** (`tests/test_lp.py`, no server is started): load `scripts/lp.py` by path with
`importlib.util.spec_from_file_location`; `lp root` (shell) equals `runtime_env.data_root()` for `LP_HOME`, for
`XDG_DATA_HOME` and for the macOS default (patch `platform`/`sys.platform` and `HOME`); `read_runtime` rejects
missing, invalid and wrongly typed JSON; `tail` returns the last N lines of a longer and of a shorter file;

## 10. Failure handling and stop conditions

| Situation | Do |
| :--- | :--- |
| `bwrap` missing or failing on Linux | Keep the engine **blocked** with the reason; record the exact command/output; continue. Do not implement the degraded fallback (P6, written approval). |
| No Linux machine available | Close the Linux rows in the checklist as "not measured, no machine"; CI proves the runtime starts. Record it. |
| `uv` cannot download CPython 3.12 | Stop. Do not use the system Python or the dev `.venv`. |
| The server does not start on macOS | Read `runtime.log`; fix the cause. Do not add a retry loop to hide it. |
| A test fails for a reason unrelated to P1 | Fix it if it is a consequence of the change; otherwise stop and report, with the failing output. Never skip, never `xfail` without a comment and an issue reference. |
| A root `.md` rewrite beyond §7.9 is needed | Stop and ask; `AGENTS.md` protects those files. |
| The new data root would overwrite existing user data | Stop. `--migrate` refuses non-empty destinations by design; ask before deleting anything. |

## 11. Handoff to P2

P2 (engine packages as downloads, `compat.py`, native ROCm) builds on these interfaces; keep them stable:

- `runtime_env.Layout` / `data_root()` — P2's installer and catalog code use the same paths, no new env names.
- `supervisor.py` — P3's Tauri shell spawns exactly `python -m app.supervisor`; its CLI flags and `runtime.json`
  schema are the contract.
- `sandbox.prefix()/problem()` — P2's `compat.py` reports the sandbox verdict; P6 replaces the Linux mechanism, not
  the call sites.
- `scripts/lp` — every install/setup command goes through it; `make` stays a thin alias.
- `docs/architecture/runtime-contract.md` — the single page P2 extends instead of duplicating.

Known gaps P1 leaves on purpose: no restart on crash, no token, no tray, no updater, no GPU-job verification on
Linux (P2), no Linux desktop packaging (P6).
